# ui-hot-reload: handoff (2026-11-13)

Goal: a tool for AC6 UI modders: edit a menu `.gfx` in the me3 package, press a key, and the game uses the edited
movie the next time the menu is opened, without restarting.

Spun off from `AC6_Projects\hud-color`, where everything below was found and tested. Read its `notes.md` (sections
"Movie cache and sortie HUD", "Menu file repository", "Disk fallback") and the probe DLL `hud-color\probe-dll\src\
lib.rs`, which already implements every piece for the HUD movie (`01_000_FE`). AC6 1.09.1, stock exe (not
UXM-patched), me3 0.13.0.

## How menu movies load (verified in Ghidra and at runtime)

- Menu table `0x144e28cf0`: 109 entries of 16 bytes {int layer, byte resident (+4), wchar* name (+8)}.
- `CSScaleformSystem` caches loaded movies in a std::map at `+0x9b8` (head `+0x9c0`; node key chars +0x28, length
  +0x30, movie wrapper at node+0x248; wrapper = 0x38 bytes, vtable `0x143b05e40`, refcount +8, slot 0 destroys).
  Lookup `0x141609040(system, out, entry)`; on a miss it loads through `0x1415faa20` -> Scaleform CreateMovie
  `0x141a4c6f0` and re-caches when resident.
- Scaleform keeps its own movie library keyed by path + mtime: the old movie must really be freed (not leaked) or
  CreateMovie hands it back without reading the file.
- The game's Scaleform file opener (`CSScaleformFileOpener`, vtable `0x143b06ea8`, OpenFile `0x1415f40b0`) reads
  only from an in-memory file repository `[0x144e245b0]`, filled by requests (`0x14160b820`; boot requests all 109
  menu files) and emptied as each movie opens. After boot, a menu's file is gone.
- **Disk fallback:** OpenFile still has a disk path for repository misses, gated by the `jnz` at `0x1415f427d`
  (`0f 85 fb 01 00 00`). Six NOPs there and a miss reads the current file from disk through CSFile. Tested on the
  HUD: release the cached movie, next lookup reads the file fresh (also after swapping the package file
  mid-session).

## Working reload recipe (HUD)

Disk fallback patched; on the game thread, at the next lookup of the movie: drop the cache node's wrapper with a
proper release (refcount at +8, destroy at zero) and null the entry; the lookup then reloads it from disk. The HUD
picks it up because its player is rebuilt each sortie.

## Open questions for the tool

- Which menus rebuild their player when reopened? Others keep a live player in a second map
  (`CSScaleformSystem+0x9d8`, created by `0x140e60235`); those may need the player torn down too.
- Is the disk fallback patch safe from launch? Boot has legitimate misses (`05_termofservice.gfx`,
  `02_gaitemstatus_general_minimum.gfx`), which would then take the disk path. So far it was only enabled after boot.
- me3 only serves package files that existed at launch (new files need a placeholder); rewriting existing ones
  mid-session is fine.
- Arxan didn't react to the patch or the hooks in our sessions; keep an eye on it.
- Hotkeys: never F6 on lugia19's machine (it doesn't reach the game).
